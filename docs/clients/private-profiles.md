# Private profiles

In chat-ui every user can build **private profiles**: personal assistants with
their own instructions, skills and tools. Only the owner can see and use a
private profile. Administrators decide which skills, MCP servers and native
tools users may pick (see [User groups and access rules](../security/groups-and-permissions.md)).

## Create and edit a profile

1. In the chat-ui sidebar, open **I miei profili** (*My profiles*).
2. Click **Nuovo profilo** (*New profile*), give it a name and choose where to
   start:
   - **Vuoto** (*Blank*): an empty profile.
   - **Copia da un profilo** (*Copy a profile*): copies the instructions and
     tools of a profile you can use. Only the items you have access to are
     copied.
   - **Con il wizard AI** (*With the AI wizard*): describe what the assistant
     should do; the AI writes the instructions and picks skills and
     integrations among those you can use. The name is optional (the wizard
     proposes one).
3. The editor opens. Fill in:
   - **Istruzioni** (*Instructions*): how the assistant behaves;
   - **Skill**: the skills it can use;
   - **Strumenti** (*Tools*): integrations (MCP servers) and native tools.
     Integrations that need credentials are set up on the **Integrazioni**
     page.
   In the editor, **Migliora con AI** (*Improve with AI*) asks the wizard to
   change the profile ("add a section on formal tone", "also use web
   search"): it updates the form, then you review and save.
4. Click **Salva** (*Save*).

The wizard writes the texts in English, like the wizard of the admin panel.
It is available to everyone who can create private profiles, even without
access to the *AI Wizard Creator* profile.

The profile then appears in every profile picker of the chat, with the badge
**Personale** (*Personal*). Use **Duplica** (*Duplicate*) on a card to start
a new profile from an existing one.

## When an administrator removes access

If an administrator removes your access to a skill or an integration that one
of your profiles uses, the profile stops using it **at once**: you do not have
to do anything. The editor lists these items under **Elementi non più
disponibili** (*Items no longer available*) and removes them when you save. If
access comes back before you save, the profile uses them again.

## Limits

- A user can have up to 10 private profiles and instructions of up to 20,000
  characters (`AION_PRIVATE_PROFILES_MAX`,
  `AION_PRIVATE_PROFILE_INSTRUCTIONS_MAX`).
- An administrator can turn off profile creation for a user or a group:
  **Accessi → Utenti**, tab **Funzioni** (*Features*) of the access rules,
  item **Profili personali**. Users keep their existing profiles and can still
  edit or delete them.
- Deleting a profile pauses the scheduled jobs that used it; chats that used
  it continue with the default profile.

## For developers

- Storage: table `user_profiles` (Alembic revision `k9h0n1f039`), one row per
  profile with owner (`users.id`), name, instructions and the three lists as
  JSON. Logic in `src/access/private_profiles.py`.
- Slug: generated by the backend, `usr_<owner hash>_<name>`, with `_2`, `_3`,
  … when the name repeats. The `usr_` prefix keeps private profiles apart from
  the global YAML profiles. The slug never changes on rename.
- Resolution: at API startup the profiles are mirrored in `profile_manager`
  (overlay, not part of `list_profiles`), so every lookup by slug works.
  `src/access/policy.py` lets only the owner use a private profile, whatever
  the profile rules say. In `get_agent` the profile is intersected with the
  owner's current rules (`effective_private_profile`) before the agent cache
  key is computed.
- `GET /profiles` returns the allowed global profiles followed by the caller's
  private ones (`"private": true`).

| Method and path | Purpose |
|---|---|
| `GET /v1/me/profiles` | Own profiles, `can_create`, limits |
| `GET /v1/me/profiles/building-blocks` | Skills, MCP servers and native tools the caller may add |
| `POST /v1/me/profiles` | Create (`name`, `description`, `instructions`, `skills`, `mcp_servers`, `native_tool_groups`) |
| `GET` / `PUT` / `DELETE /v1/me/profiles/{slug}` | Read / replace / delete (delete returns `paused_jobs`) |
| `POST /v1/me/profiles/{slug}/duplicate` | Copy any profile the caller may use (`{"name": ...}`) |
| `POST /v1/me/profiles/wizard-generate` | AI draft of a new profile (`{"prompt": ...}`); needs the create capability |
| `POST /v1/me/profiles/wizard-refine` | AI update of the editor state (`{"prompt": ..., "current_profile": {...}}`) |

Errors: `422 items_not_allowed` (with the offending ids per list),
`409 private_profiles_limit`, `403 private_profiles_not_allowed`,
`404 profile_not_found` (also for profiles of other users),
`502 wizard_failed` (the LLM did not return a usable draft).

The wizard endpoints reuse `src/runtime/wizard_generator.py` (the admin-ui
wizard) with `allowed_skills` / `allowed_mcps`: the LLM only sees the skills
and MCP servers the caller may add, and the draft is filtered again. They
return drafts only; saving always goes through the validated create / update
endpoints. The wizard reads the instructions of the `aion_wizard_creator`
profile directly, so the caller's profile rules do not apply to it.
